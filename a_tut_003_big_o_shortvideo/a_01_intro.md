## Big O

Big O explains how an algorithm's time or memory use grows when the input gets bigger.

 Big O complexities:
- **O(1) Constant Time:** takes about the same time every time.
- **O(log n) Logarithmic Time:** grows slowly, often by cutting the problem in half each step.
- **O(n) Linear Time:** takes longer as the input grows.
- **O(n²) Quadratic Time:** gets much slower as the input grows, often because of nested loops.
- **O(2ⁿ) Exponential Time:** grows exponentially, often doubling the work when the input increases by one.
- **O(n!) Factorial Time:** grows factorially, often trying every possible ordering of the input.

Lower Big O is usually better for large inputs.
